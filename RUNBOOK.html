Assumptions

  • Docker and Docker Compose are installed and running.
  • The supported app path is this repository root.
  • Local development uses docker-compose.yml.
  • Production uses docker-compose.prod.yml.
  • The app listens on port 3000 inside the container.
  • App data is SQLite.
  • Local data is stored in the Docker volume budgetspin_budgetspin-data.
  • Production data is stored in the Docker volume budgetspin-prod-data.
  • BUDGETSPIN_AUTH_SECRET signs session cookies. Keep it stable between restarts; changing it logs out existing sessions.
  • Automatic FX lookup requires outbound HTTPS access from the app container to https://api.frankfurter.dev.

Production Topology

Expected request path:

Mac browser
  -> budget-spin.ts.local
  -> /etc/hosts resolves to the server Tailscale IP
  -> Traefik on the server
  -> Docker router Host(`budget-spin.ts.local`)
  -> BudgetSpin app container on Docker network proxy

Production assumptions encoded in docker-compose.prod.yml:

  • Traefik Docker network defaults to proxy.
  • Traefik entrypoint defaults to websecure.
  • TLS defaults to enabled.
  • Hostname defaults to budget-spin.ts.local.
  • No host port is published by the app container.

Adjust those values in .env.production on the server if needed.

Production First Setup

On the server, clone or copy this repo to the target directory. The examples below use /opt/budgetspin.

cd /opt/budgetspin
cp .env.production.example .env.production

Edit .env.production and set a long random value:

BUDGETSPIN_AUTH_SECRET=replace-with-a-long-random-secret

If the Traefik Docker network is not proxy, set:

TRAEFIK_DOCKER_NETWORK=actual-network-name

If Traefik is not using websecure or does not terminate TLS for this private hostname, set the matching values:

TRAEFIK_ENTRYPOINT=web
TRAEFIK_TLS=false

Confirm the Traefik network exists:

docker network inspect proxy

Build and start production:

docker compose --env-file .env.production -f docker-compose.prod.yml build --pull=false
docker compose --env-file .env.production -f docker-compose.prod.yml up -d

Check status:

docker compose --env-file .env.production -f docker-compose.prod.yml ps
docker compose --env-file .env.production -f docker-compose.prod.yml logs --tail=100 app

Mac Hostname

Add the server Tailscale IP to /etc/hosts on the Mac:

100.x.y.z budget-spin.ts.local

Then verify resolution and route from the Mac:

curl -k -I https://budget-spin.ts.local/login

If TRAEFIK_TLS=false, use:

curl -I http://budget-spin.ts.local/login

Deployments

Normal flow:

  1. Develop locally.
  2. Run typecheck/tests locally.
  3. Commit changes.
  4. Push or otherwise make the commit available on the server.
  5. SSH to the server over Tailscale.
  6. Pull latest code.
  7. Rebuild and recreate the production container.
  8. Verify logs and /login.

This repo must have commits and a git remote before the git pull based flow works. If the server is bootstrapped by copying files instead, keep .env.production and the Docker volume on the server and do not overwrite them from the Mac.

Manual deployment on the server:

cd /opt/budgetspin
git pull --ff-only
docker compose --env-file .env.production -f docker-compose.prod.yml build --pull=false
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --remove-orphans
docker compose --env-file .env.production -f docker-compose.prod.yml logs --tail=100 app

Remote deployment from the Mac:

BUDGETSPIN_SSH_TARGET=user@server ./scripts/deploy-prod.sh

Optional deployment variables:

BUDGETSPIN_REMOTE_DIR=/opt/budgetspin
BUDGETSPIN_BRANCH=main

CI Image Gate And Accepted Risks

The image job reports vulnerabilities before enforcing the CRITICAL/HIGH gate. SARIF goes to GitHub code scanning, Trivy JSON is retained for manual DefectDojo import, and syft produces the SBOM.

Gate-only suppression. Risk acceptances live in .trivyignore-gate and apply only to the blocking gate through the workflow's explicit trivyignores input. SARIF and JSON remain unfiltered so accepted risk stays visible.

Before adding an acceptance:

  1. Verify the advisory and the exact package path reported by Trivy.
  2. Document why the vulnerable path is not reachable in BudgetSpin.
  3. Add an expiry (exp:YYYY-MM-DD) that forces re-review.
  4. Keep SARIF and JSON reporting unfiltered. Never move the file back to the default .trivyignore name unless suppressing the finding from reports is intentional.

At expiry Trivy stops honoring the entry and the gate becomes red again. Remove the entry earlier if a base-image update or runtime change eliminates the finding.

Production Data

Before destructive operations or risky migrations, create a SQLite backup from inside the app container. This uses SQLite VACUUM INTO through Node’s node:sqlite module, so it does not require the sqlite3 CLI in the image.

BACKUP="budgetspin-backup-$(date +%F-%H%M%S).sqlite"
docker compose --env-file .env.production -f docker-compose.prod.yml exec -T app node --input-type=module -e "import { DatabaseSync } from 'node:sqlite'; const db = new DatabaseSync('/app/data/budgetspin.sqlite'); db.exec(\"VACUUM INTO '/app/data/$BACKUP'\"); db.close();"
docker compose --env-file .env.production -f docker-compose.prod.yml cp "app:/app/data/$BACKUP" "./$BACKUP"

To restore from that file, stop the app first:

docker compose --env-file .env.production -f docker-compose.prod.yml down

Itaú email import (experimental)

Keep the profile disabled until the email format, matching, review and reconciliation have been validated for the intended account. A notice is not a statement or proof of settlement, and not every transaction is guaranteed to be captured.

For personal Gmail accounts IMAP is already enabled. Google documents imap.gmail.com:993 with TLS. The importer reads mail over IMAP only, authenticated with an app password (the Gmail API / OAuth path was removed). Enable 2-Step Verification and create a dedicated password at Google App Passwords. Google recommends OAuth over app passwords; they may be unavailable with Advanced Protection, security-key-only 2-Step Verification or organization accounts, and are revoked when the account password changes. See Google's guidance and Gmail IMAP settings. Prefer a dedicated mailbox: read-only IMAP mode does not limit the authority of a stolen credential. Keep the password out of commands, chat and tracked files.

Set ITAU_IMAP_HOST, ITAU_IMAP_PORT, ITAU_IMAP_USER, ITAU_IMAP_PASSWORD and a distinct random INGEST_TOKEN in the protected, untracked .env.production. The mailbox defaults to INBOX. Compose must read that file for interpolation so the app and scheduler get the same token. An exported INGEST_TOKEN in the shell takes precedence for interpolation; unset it if it differs from the value in the file.

docker compose --env-file .env.production -f docker-compose.prod.yml --profile ingest up -d
docker compose --env-file .env.production -f docker-compose.prod.yml --profile ingest ps
docker compose --env-file .env.production -f docker-compose.prod.yml --profile ingest logs --tail=50 ingest
docker compose --env-file .env.production -f docker-compose.prod.yml stop ingest

The scheduler receives only INGEST_TOKEN and INGEST_INTERVAL and calls the app over HTTP on a dedicated internal network. The traffic is not encrypted between containers, so host and network access must be trusted. The endpoint remains reachable wherever the app is reachable; its token permits triggering imports. The overlap guard is per Node process: multiple app replicas need a shared lock. Concurrent calls return 409. Endpoint errors are generic; handle operational records carefully.

The importer stores IMAP UIDVALIDITY and the last processed UID in SQLite, keyed by mailbox identity. With no cursor, or when UIDVALIDITY changes, it starts at UID 1. Each trigger processes at most ten batches of 500 UID positions, reading headers first and downloading only matching candidate bodies, limited to 1 MiB. Checkpoints are saved after a complete batch. A candidate notice that cannot be imported (any reason in Quarantine) is retained in a private quarantine by UID and UIDVALIDITY with a reason code, retried in bounded batches and surfaced as a sync error for review; the rest of the batch continues. Deleted or archived notices and locators from an earlier UIDVALIDITY remain pending for manual review. Oversized (over 1 MiB) or incomplete candidates are quarantined too instead of failing the batch. Messages removed before processing cannot be recovered. Message-ID avoids reinserting the same email, but does not reconcile distinct notices for the same purchase. Imported entries start as pending.

The supported debit purchase format requires an approved debit-card subject, merchant after Realizado en, and an amount with decimal dot in pesos or dollars; comma thousands groups are accepted. Other formats remain in the quarantine.

On the Docker host, python3 scripts/install-imap-secret.py stages a Gmail address and app password in a mode-0600 file without shell arguments or logs; use --replace for an existing file. This does not start a scheduler. The read-only probe python3 scripts/probe-imap-secret.py checks the login and opens INBOX read-only without reading messages.

Leftovers from the removed Gmail API path are no longer read. /app/data/gmail-oauth.json (OAuth client and refresh token; treat as a secret), /app/data/ingest-state/gmail-state.json (checkpoint and quarantined Gmail IDs) and the provider selector /app/data/ingest-provider. They are not deleted automatically; remove them deliberately, keeping backups in mind.

The scheduler image is pinned by digest in Compose. Review and verify a new digest when updating it. Avoid exposing compose config output because interpolation reveals secrets.

Splitwise synchronization and imported categories

The optional splitwise-ingest Compose profile triggers a separate authenticated endpoint every 3600 seconds by default (SPLITWISE_INGEST_INTERVAL); it requires the same dedicated INGEST_TOKEN configured in the app. It is disabled until explicitly started. Install the key at /app/data/splitwise-api-key. The file must be owner-only. Install the personal API key over a private stdin stream, for example from the computer that holds the file, with Docker access on the server:

docker exec -i --user 0 budget-spin-app-1 node /app/install-provider-secret.mjs splitwise < /private/path/splitwise-key

The installer refuses to overwrite an existing file. Do not put credentials in shell arguments, chat, logs or the repository. Configure the app and recreate it using the verified production image before starting either scheduler; do not rebuild an older checkout during activation. Protect the data volume and any backups containing provider files. Rotate credentials explicitly when needed.

On an installation using scripts/activate-sync.py, the Itaú check accepts the private IMAP file /app/data/imap-credentials.json or, if it is absent, ITAU_IMAP_USER / ITAU_IMAP_PASSWORD in the app; Splitwise uses /app/data/splitwise-api-key. After installing a credential, run python3 scripts/activate-sync.py itau --check or python3 scripts/activate-sync.py splitwise --check on the Docker host. To start it, repeat without --check with Docker access. It creates an owner-only trigger token, attaches the app to a dedicated internal network, and starts the selected pinned scheduler container. Its first check begins immediately. The token is mounted read-only into the schedulers, without provider credentials. The script refuses existing scheduler names and does not replace containers.

Splitwise records are stored separately by account and expense ID and are not added to budget totals. The dashboard's observed-spending view can pair them with bank notices; the rules are in FINANCIAL-RULES. The authenticated user's paid and owed shares are stored as decimal strings. Payments and deletion flags are preserved when supplied by Splitwise; records absent from a response are not assumed deleted. The page shows the latest 200 stored records and last successful synchronization. Real-account behavior and provider rate limits still need verification.

Each run is either a full pass or an incremental pass:

PassWhenWhat it requestsSaved state
Fullno watermark yet (first run, or a database from before this change), or the last full pass is 7 days old or olderevery expense updated before the run startrows, updated_watermark, full_synced_at
Incrementalotherwise (normally every hourly run)expenses with updated_after = watermark minus 5 minutes, and updated_before = run startrows, updated_watermark
  • The watermark (splitwise_sync_account.updated_watermark) is the latest provider updated_at seen in a committed pass, never the local clock. It is written in the same transaction as the rows and never moves backwards. The 5-minute overlap re-reads a few already-stored expenses; the upsert by account and expense ID makes that harmless and keeps owner-set categories.
  • A deletion is stored only when Splitwise returns the expense with deleted_at. The official API reference does not state whether get_expenses returns deleted expenses, so this is not guaranteed; a full pass does not infer deletions from absence either.
  • Pages are 20 expenses, with no item ceiling. A pass stops with an explicit reason after 5 minutes (time-budget) or 1,000 pages (page-cap). A failed or stopped pass saves nothing and leaves the watermark unchanged; the next run repeats the same window.

Inspect the sync state:

docker compose --env-file .env.production -f docker-compose.prod.yml exec -T app \
  node --input-type=module -e "import { DatabaseSync } from 'node:sqlite'; const db = new DatabaseSync('/app/data/budgetspin.sqlite', { readOnly: true }); console.table(db.prepare('SELECT synced_at, updated_watermark, full_synced_at FROM splitwise_sync_account').all()); db.close();"

To force a full pass on the next run, clear the watermark (rows and categories are kept):

docker compose --env-file .env.production -f docker-compose.prod.yml exec -T app \
  node --input-type=module -e "import { DatabaseSync } from 'node:sqlite'; const db = new DatabaseSync('/app/data/budgetspin.sqlite'); db.prepare('UPDATE splitwise_sync_account SET updated_watermark = NULL').run(); db.close();"

The optional activity extension records the most recent 100 Splitwise notifications at each successful check, retaining only supported event types linked to a stored expense where the authenticated account participates. It stores provider event IDs and times, never notification HTML. This feed is bounded and can miss earlier events. It also records each returned friend/currency balance with the observation time; it does not reconstruct earlier balances or interpret an absent balance as zero. Previously recorded observations are retained, and identical notification IDs are not duplicated. If the activity or balance API request fails, the separate expense snapshot already saved remains available, but that scheduler run reports an error and retries later.

Imported purchases receive an editable category. A prior explicit choice is reused for the same whitespace-normalized, case-insensitive description; an unknown description is assigned Other. Payments and transfers are not treated as purchases. Categories do not cause imports to be counted in budget totals.

Trigger a run by hand

Same curl form as the scheduler: the header goes to curl as config on stdin so the token is never in a process argument. Single quotes keep $INGEST_TOKEN unexpanded on the host; it is read from the scheduler container's environment.

# Compose path (scheduler running)
docker compose --env-file .env.production -f docker-compose.prod.yml --profile ingest exec ingest \
  sh -c 'printf "header = \"Authorization: Bearer %s\"\n" "$INGEST_TOKEN" | curl -K - -fsS -X POST --connect-timeout 10 http://app:3000/api/ingest/itau'
docker compose --env-file .env.production -f docker-compose.prod.yml --profile splitwise-ingest exec splitwise-ingest \
  sh -c 'printf "header = \"Authorization: Bearer %s\"\n" "$INGEST_TOKEN" | curl -K - -fsS -X POST --connect-timeout 10 --max-time 600 http://app:3000/api/ingest/splitwise'

# Script path: the token is the mounted file
docker exec budgetspin-gmail-scheduler \
  sh -c 'printf "header = \"Authorization: Bearer %s\"\n" "$(cat /run/ingest-token)" | curl -K - -fsS -X POST --connect-timeout 10 --max-time 600 http://app:3000/api/ingest/itau'

An Itaú pass answers {"ok":true,"messagesSeen":…,"inserted":…,"skipped":…}; Splitwise answers {"ok":true}.

Quarantine

A message that passed the sender/subject filter but cannot be imported is set aside with a fixed reason code; only its locator is stored (IMAP UID + UIDVALIDITY in imap-quarantine-<mailbox-hash>.json under the state directory), never the body. Each pass first retries up to 20 retained items; one that now imports is removed.

ReasonMeaning
unrecognizedbody format not understood, or no Message-ID
non_positive_amountamount is zero or negative
unconfigured_currencycurrency not configured in the app (add it, the retry can then import it)
unsupported_precisionmore decimals than the currency's minor unit
invalid_amountamount could not be converted
oversizedmessage over 1 MiB
incompletedownload incomplete or malformed headers
While anything is retained, the pass is recorded with status = 'error' and Unrecognized notices retained for review., but the route still answers 200 {"ok":true}, so the scheduler logs nothing: check ingest_runs or /transactions. Once 1000 items are retained, a pass that needs to retain one more fails. The code has no command to remove an entry by hand.

Find the trusted authserv-id (once per mailbox provider):

  1. In the mailbox web UI, open a real bank notice and choose "Show original" (or "View source" / "View message source").
  2. Find the topmost Authentication-Results: header. Do not use ARC-Authentication-Results. The authserv-id is the first token, before the first ;.
  3. Check two or three notices, and one message from an unrelated sender: the topmost authserv-id should be the same in all of them (it identifies the provider, not the sender). If it differs between messages, leave the variable unset and note it in MEJ-002.

Set it in the untracked .env.production, then recreate the app so it reads the file again:

# .env.production
ITAU_IMAP_AUTHSERV_ID=<mailbox-provider-authserv-id>

docker compose --env-file .env.production -f docker-compose.prod.yml up -d --force-recreate app
Unset or blank: only the topmost header is used, which is weaker (it relies on the provider always adding its own header). Set: only the topmost header with that authserv-id is used; any other is ignored. The verdict is computed once, at import; changing the variable does not recompute older rows.

The page header shows "N pending unverified" when any pending notice is fail or none (among the latest 200 imports). Discard a forged notice with Discard, as before. Counts by verdict and review state:

docker compose --env-file .env.production -f docker-compose.prod.yml exec -T app \
  node --input-type=module -e "import { DatabaseSync } from 'node:sqlite'; const db = new DatabaseSync('/app/data/budgetspin.sqlite'); console.table(db.prepare('SELECT t.sender_auth, COALESCE(r.decision, t.status) AS status, COUNT(*) AS notices FROM transactions t LEFT JOIN transaction_reviews r ON r.transaction_id = t.id GROUP BY t.sender_auth, status ORDER BY t.sender_auth, status').all()); db.close();"

If real bank notices come out fail or none, record what the topmost header showed (results only, no addresses) in MEJ-002 before deciding on enforcement.

Stopping a scheduler does not revoke the token: the routes still accept it from anything that can reach the app. Remove or rotate the token to fully disable.

Troubleshooting

Check production config rendering:

docker compose --env-file .env.production -f docker-compose.prod.yml config

Check Traefik can see labels:

docker compose --env-file .env.production -f docker-compose.prod.yml ps
docker inspect budgetspin-app-1 --format '{{json .Config.Labels}}'

Check the app directly from the server container namespace:

docker compose --env-file .env.production -f docker-compose.prod.yml exec app node -e "fetch('http://127.0.0.1:3000/login').then(async r => { console.log(r.status); process.exit(r.status < 500 ? 0 : 1); }).catch(error => { console.error(error); process.exit(1); })"

Common failures:

  • network proxy declared as external, but could not be found: set TRAEFIK_DOCKER_NETWORK to the server’s actual Traefik network or create the proxy network.
  • BUDGETSPIN_AUTH_SECRET missing: create .env.production from the example and set a stable random secret.
  • Browser cannot resolve budget-spin.ts.local: update /etc/hosts on the Mac with the server Tailscale IP.
  • Browser resolves but Traefik returns 404: verify hostname, entrypoint, TLS, labels, and Docker network.
